# PromptPro 官网 SEO 规划

更新时间：2026-08-20

## 1. 文档目标

本文档用于规划 PromptPro 官网的产品定位、SEO 页面结构、关键词布局、转化路径和开发阶段。

官网的首要任务不是建设复杂 SaaS，而是承担三个职责：

1. 解释 PromptPro 解决的问题；
2. 建立“本地优先、无需账号、提示词不上传”的信任；
3. 将自然搜索流量和产品访问者转化为 Chrome 插件安装用户。

## 2. 产品定位

推荐定位：

> PromptPro 是一个面向 AI 网站的本地优先提示词优化器与模板库。

英文定位：

> A local-first prompt optimizer and template library for AI websites.

PromptPro 不应主要与竞品比较“谁的在线 AI 改写能力更强”，而应突出当前产品已经具备的差异化：

- 提示词在浏览器本地处理；
- 无需注册账号；
- 不需要把提示词上传到新的远程服务；
- 直接在支持的 AI 网站中优化或插入提示词；
- 66 个中英双语模板；
- 支持写作、编程、营销、职场、翻译、学术、分析和创意等场景。

## 3. 竞品观察

Pretty Prompt 官网已经形成“产品首页 + 功能页 + 平台/场景页 + 内容入口 + Chrome 安装”的增长结构。其首页使用 “Grammarly For Prompts” 作为定位，并覆盖 ChatGPT、Claude、Gemini、Prompt Optimizer、Prompt Templates、Writing、Coding、Marketing、SEO、Research 等主题。[Pretty Prompt 官网](https://www.pretty-prompt.com/)

竞品值得借鉴的不是页面数量本身，而是以下结构：

```text
搜索关键词
  -> 功能页 / 平台页 / 场景页
  -> 产品解释与信任证明
  -> Chrome Web Store 安装
  -> 用户评价和真实数据
```

PromptPro 第一阶段不需要复制竞品的复杂功能面，应先占据“隐私、本地、无需登录、双语模板”的细分位置。

## 6. 页面规划

### 6.1 首页 `/`

主关键词：`local AI prompt optimizer`、`prompt templates`、`ChatGPT prompt optimizer extension`

标题建议：

```text
PromptPro — Local AI Prompt Optimizer & Prompt Templates
```

中文标题：

```text
PromptPro｜本地 AI 提示词优化器与模板库
```

首页结构：

1. 首屏定位和安装按钮；
2. 支持平台；
3. 一键优化功能；
4. 模板库和分类；
5. 使用流程；
6. 本地隐私说明；
7. 使用场景；
8. FAQ；
9. 最终安装 CTA。

首屏文案方向：

```text
Improve your AI prompts locally.

PromptPro helps you write clearer prompts and reuse proven templates
inside ChatGPT, Claude, Gemini, DeepSeek and more.

No account. No prompt uploads. No automatic message submission.
```

### 6.2 功能页 `/features`

主关键词：`AI prompt optimizer extension`、`prompt template library`、`prompt manager extension`

内容包括：

- 一键优化；
- 66 个中英双语模板；
- 模板搜索；
- 自定义模板；
- 变量；
- 优化历史；
- 撤销；
- 中英双语界面；
- 本地存储。

每个功能最好配真实截图或短 GIF，并指向 Chrome Web Store。

### 6.3 隐私页 `/privacy`

主关键词：`private prompt optimizer`、`prompt optimizer without login`

必须回答：

- 是否需要账号；
- 提示词是否上传；
- 是否使用远程 AI API；
- 数据保存在哪里；
- 是否有分析、广告或遥测；
- 是否自动发送消息；
- 使用了哪些浏览器权限；
- 如何清除本地数据。

隐私页面必须与代码、Chrome Web Store 描述和实际发布版本保持一致。不要在没有验证的情况下宣传“完全离线”或“零数据收集”。

### 6.4 平台页 `/platforms`

优先制作：

- `/platforms/chatgpt`
- `/platforms/claude`
- `/platforms/gemini`
- `/platforms/deepseek`

每个平台页应包含平台说明、实际支持的操作、产品截图、推荐模板、安装按钮和 FAQ。

当前扩展配置的支持站点还包括豆包、Perplexity、Copilot、Grok、Google AI Studio、Cursor、v0 和 Lovable。后续只有在真实 Chrome 验证通过后，才应在官网公开承诺对应能力。

### 6.5 模板页 `/templates`

优先制作：

- `/templates/writing`
- `/templates/coding`
- `/templates/marketing`
- `/templates/academic`

每个分类页应包含分类介绍、适用人群、精选模板、使用示例、相关页面和安装 CTA。至少展示 3—5 个真正可用的免费模板，避免只有 SEO 文案没有产品价值。

### 6.6 使用场景页 `/use-cases`

后续可增加：

- `/use-cases/writing`
- `/use-cases/coding`
- `/use-cases/marketing`
- `/use-cases/students`
- `/use-cases/research`
- `/use-cases/translation`

模板页回答“我想找一个可以直接用的 Prompt”；场景页回答“我想用 AI 完成某类工作”。两类页面应避免使用完全相同的内容。

## 8. 技术 SEO 清单

官网上线时至少需要：

- 每页独立的 `title`；
- 每页独立的 `description`；
- canonical URL；
- `sitemap.xml`；
- `robots.txt`；
- Open Graph 图片；
- Twitter Card；
- favicon；
- 中英文 `hreflang`；
- 清晰的 H1/H2 层级；
- 图片 `alt` 文本；
- 页面内链；
- `SoftwareApplication` 结构化数据；
- `Organization` 和 `WebSite` 结构化数据；
- FAQ 页面中的 `FAQPage` 结构化数据；
- 教程页面中的 `Article` 和 `BreadcrumbList` 结构化数据。

性能上应优先静态生成、压缩截图、减少首屏 JavaScript 和第三方脚本。隐私定位下不建议默认引入大量跟踪代码。

```text
/en/
/en/features/
/en/platforms/chatgpt/
/en/templates/coding/

/zh-CN/
/zh-CN/features/
/zh-CN/platforms/chatgpt/
/zh-CN/templates/coding/
```

英文页面重点覆盖平台、插件和场景关键词；中文页面重点覆盖提示词优化、平台使用方法、模板和隐私关键词。中文页面和英文页面应分别改写，不建议直接机器翻译。

## 10. 转化设计

所有页面都应有明确 CTA：

```text
Add to Chrome
Explore Prompt Templates
See How It Works
```

推荐导航：

```text
Features · Platforms · Templates · Privacy · Guides · Install
```

安装 CTA 至少出现三次：首屏、主体内容之后、页面底部。所有安装按钮统一指向 PromptPro 的 Chrome Web Store 页面：

[PromptPro Chrome Web Store](https://chromewebstore.google.com/detail/promptpro-local-prompt-op/lakcfmbmainingemilkajglcmlplkhdj?authuser=0&hl=zh-CN)

不要在早期官网中主动制作竞品对比页，否则容易把用户注意力带到竞品品牌上。除非后续有明确的对比搜索需求和足够可靠的事实数据。

页面：

```text
/
/features
/privacy
/platforms
/templates
/about
```

完成标准：

- 首屏能在几秒内说明产品价值；

- 有真实产品截图；
- 支持平台和隐私说明准确；

- 有 sitemap、robots 和基础结构化数据；
- 接入 Google Search Console；
- 不修改扩展的既有隐私边界。

### 阶段二：平台和模板 SEO

增加 4 个平台页和 4 个模板分类页。每页提供真实的产品使用说明、截图、FAQ 和安装 CTA。

### 阶段三：教程内容增长

每周发布 1—2 篇高质量教程，优先覆盖：

- 如何写更好的 ChatGPT 提示词；
- ChatGPT 编程提示词模板；
- DeepSeek 提示词优化；
- Claude 和 Gemini 使用方法；
- 提示词隐私和本地工具；
- 如何管理可复用提示词。

教程应解决真实问题，并自然引导到 PromptPro，而不是批量生成相似页面。

## 12. 风险和边界

### 不要夸大 AI 能力

如果功能主要依赖本地规则、模板和本地处理，不要声称使用“最先进的 AI 模型”或云端 AI 改写。

### 谨慎使用“完全离线”

“本地处理”“无需账号”“提示词不上传”和“完全离线”不是完全等价的表达。只有在运行链路实际满足时，才能使用“完全离线”。

### 不要伪造社会证明

没有真实安装量、评价、用户数或案例时，不要写虚构的用户数据、优化次数、公司 Logo 或评分。可以优先使用真实截图、公开更新日志、Chrome Web Store 评价和隐私透明度建立信任。

### 保持产品文案与实现一致

官网、Chrome Web Store、隐私页面和扩展代码必须同步。涉及平台支持、权限、存储、远程请求、统计和自动提交行为时，必须以真实验证结果为准。

## 14. 最终优先级

建议按以下顺序执行：

1. 高转化首页；
2. 隐私页；
3. ChatGPT、Claude、Gemini、DeepSeek 平台页；
4. Writing、Coding、Marketing、Academic 模板页；
5. Search Console 和 sitemap；
6. 5—10 篇高质量教程；
7. 根据搜索曝光、安装点击率和 Chrome 安装数据扩展页面。

最需要验证的核心假设是：

> “本地、不上传、无需登录的提示词工具”是否能够显著提升用户的安装意愿。

这个方向比单纯复制 Pretty Prompt 的在线功能数量更适合 PromptPro 当前的产品能力和个人开发者资源限制。
