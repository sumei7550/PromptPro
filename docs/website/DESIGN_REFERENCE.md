# PromptPro 官网设计参考与冻结决策

更新时间：2026-08-24

本文档用于记录 PromptPro 官网设计方向的参考来源、可学习点和不采用点，并冻结首版官网的关键视觉与营销决策。

本文档只涉及官网信息表达和视觉设计，不修改 Chrome 扩展代码，也不代表官网已经上线。当前 checkpoint 已冻结 Brand Logo Final、CTA Visual Refinement、Header/Footer IA v2、Homepage、Features 和 CTA system；官网公开文案仍必须以产品事实、当前验证状态和隐私边界为准。

## Website IA v2 冻结补充

- URL strategy：English 为 default locale，根路径 `/` 直接渲染英文首页；英文页面不使用 locale 前缀，中文页面使用 `/zh-CN`，所有正式 URL 禁用 trailing slash。
- Header 使用一层导航：Features、Platforms、Templates、Pricing；不做 Product/Resources Mega Menu。
- Language Switcher 使用 Globe + 当前语言 + Chevron 的下拉形式，只显示 English 与简体中文，并保留当前页面路径。
- Header/Footer 的 Add to Chrome CTA 在 Chrome Web Store URL 未冻结前保持 disabled/unavailable；不得填入占位 URL。
- Footer 左侧为 PromptPro 品牌区域、事实审查后的 1–2 行定位、Add to Chrome 和 Privacy Policy/Terms of Use；不创建社交入口或独立 Install 列。
- Footer 分组为 Product、Resources、Company；Pricing、FAQ、Support、Changelog、About、Terms of Use 无真实正文前只保留 IA，不创建空路由。
- Pretty Prompt 仅参考信息分组和未来 Use Cases 扩展思路；SaveAI 仅参考语言入口与 CTA 层级，不复制其账号或 Profile 能力。

## 2. Pretty Prompt

### 可学习点

- **一句话定位非常直接**：使用“Grammarly For Prompts”这样的类比，快速让用户理解产品属于“改善输入、获得更好 AI 结果”的工具。
- **Hero 先讲结果，再讲产品类别**：将“更好的提示词”和“一键获得更好的 AI 结果”放在首屏核心位置，降低用户理解成本。
- **首屏能看到产品范围**：同时展示支持的 AI 平台、核心功能入口和安装 CTA，用户可以快速判断是否与自己的工作流相关。
- **功能架构完整**：Prompt Optimizer、Playground、Image to Prompt、Prompt Metadata、Prompt Templates 等功能被组织成清晰的导航和功能入口，适合借鉴“从单一卖点延伸到产品能力地图”的结构。
- **使用场景覆盖广**：将 Writing、Coding、Marketing、SEO、Research、Non-Native English 等场景单独列出，有利于后续 SEO 页面和用户自我归类。
- **真实使用反馈增强可信度**：在产品说明之后放置用户评价、来源标签和演示视频，形成“功能说明 → 使用证据”的阅读链路。
- **CTA 重复但目标一致**：页面中多次出现免费试用/安装入口，降低用户读完页面后重新寻找入口的成本。

### 不采用点

- **不采用“Grammarly for Prompts”作为 PromptPro 主定位**：类比有助于理解，但会把用户预期绑定到 Grammarly 的成熟度、产品范围和商业模式；PromptPro 首版应直接说明“本地提示词优化 + 双语模板 + 支持的 AI 网站内插入”。
- **不复制多产品线扩张的首页密度**：Pretty Prompt 同时展示大量工具、MCP、Canvas、Chat 等能力，容易让独立开发者产品首版显得范围过大。PromptPro 首屏只突出已确认的核心流程。
- **不使用客户 Logo 墙或未经核实的社会证明**：PromptPro 当前没有可公开核验的企业客户、用户数量或评分证据，不使用装饰性 Logo 来制造成熟度。
- **不使用未经当前验证的数据**：例如安装量、改善次数、评分和“全球用户”等数字，除非发布前有对应的最新证据并完成事实审查。
- **不把大量用户评价当作首版核心内容**：评价可以作为后续增强模块；首版优先解释产品如何工作、隐私边界和实际安装路径。
- **不将过多平台/场景并列成主视觉**：平台和场景可以作为辅助信息或独立页面入口，不让首屏变成平台 Logo 展示墙。

## 3. SaveAI interaction reference

### 可学习点

- Language Switcher 使用 Globe、当前语言和 Chevron 的紧凑组合。
- Dropdown 内显示 English 与简体中文，并突出当前语言。
- Add to Chrome 作为 Header 的明确 Primary CTA。

- 不提前显示未提供的语言。

## 4. Promptly

### 可学习点

- **Hero 信息层级简单**：标题、短说明、安装 CTA 和 Demo 入口组成清晰的首屏操作路径。
- **“三步开始”适合借鉴**：Install Extension → Open Any AI Chat → Enhance Your Prompts，把安装后的最短成功路径表达得很直观。
- **功能分组容易扫描**：Prompt Engineering Tools、Prompt Library & Organization、Cross-Platform Chat Export 等模块让用户可以按任务理解产品。
- **平台兼容性独立呈现**：将支持的平台单独列出，适合 PromptPro 以“已验证/历史验证/代码配置未验证”的状态分组表达，而不是笼统写成全部支持。
- **FAQ 承接购买前疑问**：隐私、工具工作方式、模板管理和跨平台能力适合在官网后半段回答，减少用户因关键疑问离开页面。
- **首屏和页面末尾均有 CTA**：对长页面有效，用户不必返回顶部才能安装。

### 不采用点

- **不采用“10,000+ users”“4.5 Chrome Web Store”“100% Free”等数字化背书**：PromptPro 当前没有对应的最新公开证据，不能为了转化率填入推测数字。
- **不采用“all major AI platforms”“works with ... and more”式的宽泛承诺**：平台支持必须以当前代码配置和真实 Chrome 验证为边界；“已配置”不能等同于“稳定可用”。
- **不宣传跨平台会话导出或绕过使用限制**：这不是 PromptPro 当前首版的核心能力，也会引入额外的隐私、平台规则和维护风险。
- **不采用 API Playground、登录入口或账号产品结构**：PromptPro 官网首版保持静态、无账号、无后台，核心转化目标是 Chrome Web Store 安装。
- **不使用“Free Forever”“No credit card”等尚未冻结的商业承诺**：是否永久免费、是否商业化以及未来套餐均应单独决策，不能由参考网站的文案倒推。
- **不把 FAQ 作为空壳 SEO 区块**：每个问题必须有真实、可验证的回答，不能只列问题标题来制造页面长度。

## 5. Prompt Sloth

### 可学习点

- **产品动作表达具体**：把“粗略的一句话”变成“详细、结构化提示词”，比泛泛描述“提升 AI 效果”更容易理解。
- **强调产品在原工作流内运行**： “right inside ChatGPT ... without switching tabs”清晰表达了浏览器插件的便利性，PromptPro 可以借鉴“在 AI 网站当前输入框中完成优化和插入”的表达方式。
- **一键动作和模板快捷入口形成连续工作流**：Improve 按钮与模板快捷方式并列，体现从临时优化到长期复用的产品路径。
- **Feature 展示有明确的操作结果**：每个功能都围绕“用户原本做什么、PromptPro 改变什么、最终得到什么”展开，适合用真实截图和简短说明呈现。
- **定价结构可作为商业化研究样本**：Free、Pro、Lifetime Pro 的差异、限制和升级理由表达清楚，便于未来评估 PromptPro 的商业化路径。
- **隐私区块单独出现**：将历史记录、模板和账号数据分别说明，提醒官网必须把隐私边界作为产品内容而非页脚小字。
- **内容型 SEO 入口丰富**：教程、免费工具、职业模板、比较页和替代方案页具有长期获客潜力，可作为 PromptPro 后续内容规划的参考。

### 不采用点

- **不采用强压迫式营销语气**：例如“unfair advantage”“every rough draft is a missed opportunity”等焦虑驱动表达。PromptPro 使用清晰、克制、可验证的价值说明。
- **不复制“10,000+ users”、研究数据或“20+ tools”卖点**：除非 PromptPro 未来拥有自己的证据和合规引用，否则不使用竞品的社会证明或研究数字。
- **不在首版引入账号、云端加密历史或同步承诺**：PromptPro 当前定位是本地优先，设置、个人模板和优化历史存储在 `chrome.storage.local`，不应为了视觉或营销形式暗示云端账户体系。
- **不提前引入订阅、终身买断和复杂限额**：商业化可以作为后续阶段研究，不在没有产品计量、支付、服务端和隐私方案时进入首版官网。
- **不把桌面端、终端、跨应用快捷键或候补名单作为当前产品能力**：这些属于参考网站的扩展路线，PromptPro 首版只承诺已经实现并验证的 Chrome 扩展流程。
- **不大量堆叠比较页、替代方案页和职业模板页**：内容 SEO 是后续增长方向，不以牺牲首版官网的可信度和维护成本为代价提前铺开。
- **不使用账号安全、加密、隐私保护等无法由当前实现证明的表述**：PromptPro 只能准确说明本地存储和不新增远端处理，不扩展为未经验证的安全承诺。

## 6. 三个参考网站的共同结论

### 可以统一借鉴

- 首屏必须在几秒内说明：PromptPro 是什么、解决什么问题、用户下一步做什么。
- 产品动作比抽象口号更有效：展示“输入粗略提示词 → 优化 → 插回当前 AI 网站”的前后关系。
- Feature 区块应围绕用户任务组织，而不是只罗列技术名词。
- 安装 CTA 应贯穿长页面，但每个区块只保留一个主动作，避免多个同权重按钮互相竞争。
- 平台兼容性、模板能力、隐私说明和 FAQ 应成为可独立阅读的内容模块。
- 真实产品界面、动图或短 Demo 的说服力高于装饰性插画，但素材必须来自已实现功能。

### PromptPro 的明确差异

- **本地优先**：强调提示词、模板、设置和历史在本地保存，不把产品包装成云端 AI 工作台。
- **双语模板**：突出中英文模板和双语使用体验，这是 PromptPro 相对英文竞品可以形成的清晰切入点。
- **隐私表达克制**：只承诺代码和产品事实能证明的范围，不将“本地优先”夸大为全面安全保证。
- **平台状态透明**：分开表达当前版本已验证、历史验证和代码配置未验证，避免用一个“支持平台”列表掩盖事实差异。
- **独立开发者可维护**：首版官网保持页面少、内容清晰、静态优先，不追求竞品式的大型产品矩阵。

## 7. PromptPro 最终冻结

以下决策作为 PromptPro 官网首版的设计基线。后续页面实现、素材制作和文案调整不得无理由偏离；如产品事实、隐私边界或 Chrome Web Store 状态发生变化，应先更新事实文档，再评估是否需要解除冻结。

### 6.1 官网视觉方向

**冻结为：清晰、克制、产品导向的 Light Theme 官网。**

- 使用白色和轻微紫灰色作为主要背景，保持阅读区域干净。
- 以现有产品图标的紫色/靛蓝色作为品牌主色，用于主 CTA、链接、焦点状态和少量装饰。
- 暖黄色只作为小面积品牌亮点，不承担正文、警告或功能状态语义。
- 使用真实产品界面作为主要视觉证据；插画只能辅助解释，不能代替功能截图。
- 卡片使用轻边框、适度圆角和克制阴影，不做复杂玻璃拟态、重拟物或大面积渐变。
- 首版只做 Light Theme，不为视觉炫技增加 Dark Theme、复杂动画或高维护成本的交互。
- 视觉优先级固定为：产品是什么 → 如何工作 → 为什么可信 → 如何安装。

### 6.2 Hero 方向

**冻结为：结果导向 + 产品类别说明 + 真实工作流视觉。**

Hero 必须包含：

1. 一个直接说明结果的主标题，例如“让 AI 更容易理解你的提示词”这一类方向；
2. 一段说明 PromptPro 是本地提示词优化和模板工具的短描述；
3. 一个明确的 Chrome Web Store 主 CTA；
4. 一个低权重的次 CTA，用于查看功能、模板或工作方式；
5. 一个真实的产品视觉，展示输入、优化和插入其中至少一个关键动作；
6. 如需展示平台，只展示当前事实允许的范围，并使用透明的状态说明。

Hero 不采用：

- 空泛的“重新定义 AI”“释放无限潜能”等不可验证口号；
- 竞品式用户数量、评分、客户 Logo 或夸张效果数字；
- 同时放置多个同等权重的安装、登录、注册、购买按钮；
- 首屏堆叠所有功能、所有平台和所有模板分类；
- 将尚未真实验证的平台写成稳定支持。

### 6.3 产品截图使用方式

**冻结为：真实截图、完整语境、少裁剪、旁边配可索引说明。**

- 只使用已实现的 PromptPro 扩展界面截图，不使用 AI 生成的 UI 截图作为功能证据。
- 截图优先展示真实任务流程：输入粗略提示词、点击优化、查看结果、插入 AI 网站输入框或使用模板。
- 保留浏览器/页面语境中足以理解功能的部分，不只截取孤立按钮或装饰性 Popup。
- 不通过 `cover` 强行裁切核心界面；素材比例不合适时使用原始比例或容器留白。
- 截图旁边必须有文字说明，解释用户看到的动作和价值；关键内容不能只存在图片里。
- 截图使用版本和平台必须可追溯，发布前确认截图与当前构建一致。
- 涉及提示词、历史或模板时使用脱敏示例，不放入真实个人或敏感内容。
- 移动端允许截图自然缩放，但不能因为缩小导致核心文字无法理解；必要时拆成步骤图，而不是无限压缩一张长图。

### 6.4 Feature 展示方式

**冻结为：以用户任务为中心的 3–4 个核心能力区块，逐步展开，不做功能墙。**

首版优先展示：

- **Prompt Optimizer**：把粗略意图整理成更清晰、更结构化的提示词；
- **In-page Insert**：在支持的 AI 网站当前工作流中完成优化结果写回/插入；
- **Bilingual Templates**：通过中英文模板快速开始常见任务；
- **Local History & Personal Assets**：本地保存个人模板、设置和优化历史，具体边界以产品事实为准。

每个 Feature 使用固定结构：

1. 用户场景或问题；
2. PromptPro 的动作；
3. 用户得到的结果；
4. 一张对应的真实截图或简短流程图；
5. 必要时补充隐私、平台状态或使用边界。

Feature 展示不采用：

- 六到十几个同等权重的功能卡片；
- 只有图标和一句空泛价值的卡片；
- 把未来规划、代码配置和当前可用能力混在一起；
- 使用模板数量、平台数量、准确率或效率倍数作为未经验证的卖点。

### 6.5 CTA 策略

**冻结为：单一主转化目标，低压力、多位置、事实透明。**

- 官网首版主转化目标是 Chrome Web Store 安装。
- Header、Hero、核心功能说明后和页面底部可以重复出现安装 CTA，但每个区块最多一个 Primary CTA。
- Primary CTA 文案直接说明动作，例如“Add to Chrome”/“添加到 Chrome”；不使用模糊的“开始改变一切”。
- 次 CTA 用于“查看功能”“查看模板”“了解隐私”或“查看工作方式”，不与安装 CTA 争夺同等视觉权重。
- CTA 附近可以说明“无需账号”等已经确认的事实，但不得加入未经冻结的永久免费、无信用卡、无限使用等承诺。
- 外链按钮要明确目标并保留可访问名称；不伪造加载状态，不自动打开多个页面，不自动执行提交。
- CTA 视觉保持品牌色、足够对比度和清晰焦点状态；不使用弹窗拦截、倒计时、虚假稀缺和强迫订阅。

### 6.6 不采用的营销方式

PromptPro 官网首版明确不采用以下营销方式：

- 虚构或未经核实的用户数、安装数、评分、客户 Logo、评价和性能提升数字；
- 夸大平台覆盖范围，或把“代码已配置”写成“当前稳定支持”；
- 以焦虑、羞耻、错失机会或“竞争优势”制造点击压力；
- 虚假倒计时、限时优惠、假装排队、自动弹窗和遮挡式订阅收集；
- 未经批准的远端 AI 处理、账号、云同步、遥测或数据收集暗示；
- 把隐私、安全、加密、合规写成无法由当前实现证明的绝对承诺；
- 在首版加入订阅、终身买断、复杂免费额度或价格锚定，除非商业化方案已经单独冻结；
- 大规模复制竞品的比较页、替代方案页和职业模板页，造成维护成本高于真实产品价值；
- 使用 AI 生成的产品界面、虚构案例或无法追溯来源的 Demo 作为功能证明；
- 通过关键词堆砌、重复 FAQ 或大量薄内容换取 SEO 流量。

## 8. 执行边界
